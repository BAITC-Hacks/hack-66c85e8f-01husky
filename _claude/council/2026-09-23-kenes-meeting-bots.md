# Kenes AI: подключение бота к встречам

Scope: Large. Основа: origin/develop ba6e963, объединена с nikita. Локального AGENTS.md нет; учитываются agents/CONTEXT.md и PROTOCOL.md. Никита передал bots/ от Ардака агенту B и поручил реализацию Teams, Zoom и Google Meet. Телемост опционален.

## Рецензенты

Engineer: runtime, процессы и аудиозахват. Privacy: callback, ссылки, записи. Product: критерии готовности всех трёх платформ. Отдельные именованные specialist-роли из policy недоступны в текущем каталоге; эти проверки покрываются выбранными ролями и тестами.

## Выводы engineer

Cleanup текущего base.py не охватывает join/lobby/start_recording. Цикл не замечает падение ffmpeg. Timeout subprocess не завершает группу дочерних процессов. Образ не содержит Chromium/PulseAudio. Нужны отдельный bot-worker и очередь, concurrency=1, проверка WAV, cleanup и тест каждого этапа.

## Выводы privacy

Общий callback token в argv и опубликованное значение по умолчанию позволяют подмену аудио. URL только length-validated. Общий Pulse sink смешивает параллельные звонки. Нужны scoped JWT с отдельной audience и нечисловым subject, env вместо argv, фильтр URL, временные записи и профиль, очистка при ошибках. Полный URL/ответ API в логах недопустимы.

Повторный privacy review снял прежний veto: общий fallback удалён; сервер проверяет meeting_id, source=bot, стадию, audience и срок. URL/token вынесены из argv; пустые и известные default signing keys отклоняются. Private файлы исключены из Docker context. Полная сетевая изоляция не заявляется.

## Выводы product

Для каждой платформы: гостевой вход при разрешении организатора, видимое имя Kenes AI с указанием записи, mute mic, статичный логотип вместо камеры, ожидание допуска с timeout, минимум минута слышимой тестовой речи двух участников, корректный выход, однократная загрузка и переход в draft. Mock/HTML fixtures не подтверждают поддержку действительного клиента.

## Решение и план

1. Общий браузерный lifecycle, отдельные адаптеры Meet/Zoom/Teams на web-клиентах. Auth-required/CAPTCHA/denied дают понятную ошибку; обхода ограничений нет.
2. Бот читает разрешённую HTTPS-ссылку выбранной платформы, использует свежий browser context и виртуальные устройства: беззвучный микрофон и статичный логотип. Redirect/локальные сетевые назначения ограничены.
3. Отдельный bot-worker/queue, одна запись одновременно. Linux runtime с Chromium, Xvfb и выделенным PulseAudio. ML worker остаётся доступным.
4. Backend передаёт только meeting_id в задачу. URL читается из БД, callback token выдаётся конкретной встрече и передаётся subprocess через env. Browser child не получает token, DB credentials и AI keys.
5. Запись и браузер завершаются при успехе, ошибке и timeout. Пустой/невалидный WAV не считается результатом. Запись удаляется после передачи или неуспеха.
6. Юнит/контрактные проверки и браузерные HTML fixtures выполняются локально; Chromium audio smoke в Linux/Docker. Живые звонки проверяются отдельно по ссылкам Никиты.

## Открытые вопросы

Никита выбрал guest-first и предоставил тестовые ссылки Meet, Zoom и Teams. Ссылки хранятся только во временном приватном файле, в git их нет. Независимая работа по runtime, scoped callback и guest lifecycle уже разрешена запросом реализации. Закрытые встречи без разрешённого guest потребуют отдельной учётной сессии. Проверку реальных платформ нельзя заменить локальными тестами.

## Отложено

Телемост до обязательной тройки, автосоздание встреч, календарь, официальные SDK, параллельные записи, новые UI-фичи вне существующей формы.

## Готовность

Критерии завершения: Engineer проверяет cleanup, запись и runtime; Privacy проверяет scoped token, URL и изоляцию; Product проверяет живой отчёт для каждой платформы. Локальные регрессии пройдены, контейнерный runtime и живые записи ещё не подтверждены.
