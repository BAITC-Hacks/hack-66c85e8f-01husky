# Локальные поручения, саммари и имена спикеров

Реальный пайплайн (`PIPELINE_FAKE=0`) выполняет Whisper → sherpa-onnx → локальную
Qwen3:8b через Ollama. На Mac с 16 ГБ RAM используется квантованная модель около
5,2 ГБ; обработка добавляет несколько минут в зависимости от длины встречи.

## Подготовка (macOS)

Из корня репозитория:

```bash
brew install ollama
uv sync --project backend --extra stt
backend/.venv/bin/python scripts/local_llm.py
```

Последняя команда остаётся работать в терминале. Она слушает **127.0.0.1:11434**,
задаёт `OLLAMA_NO_CLOUD=1`, хранит веса в игнорируемом `pipeline/.models/ollama`.
В другом терминале один раз скачайте веса (аудио и текст при этом не передаются):

```bash
OLLAMA_HOST=127.0.0.1:11434 ollama pull qwen3:8b
```

Настройки корневого `.env`:

```dotenv
PIPELINE_FAKE=0
LLM_PROVIDER=ollama
LLM_MODEL=qwen3:8b
OLLAMA_URL=http://127.0.0.1:11434
LLM_TIMEOUT_SEC=300
LLM_CONTEXT_TOKENS=12288
DIARIZATION_BOUNDARY_GRACE_SEC=1.2
```

Перезапустите API/worker (`local_dev.py stop`, дождитесь остановки, затем `start`).
Ollama запускается отдельно и не останавливается командой `local_dev.py stop`.
Для Compose используется внутренний адрес `http://ollama:11434`; облачный режим
отключён в сервисе `ollama`. В закрытый контур перенесите веса заранее: при
обработке модели **не скачиваются**, внешнего fallback нет.

## Проверяемая цепочка

1. Обрывы ASR внутри одного предложения одного спикера объединяются (пауза ≤0,7 с,
   не более 20 с/700 символов). Транскрипт с индексами делится на ограниченные
   фрагменты с перекрытием контекста.
2. Qwen возвращает кандидатов по JSON Schema: действие, имя, исходный срок, цитата.
3. Код проверяет наличие дословной цитаты в указанном сегменте. Выдуманная цитата
   отбрасывается. Имена/сроки без текстового основания не назначаются.
4. Второй запрос по цитатам (без остального транскрипта) проверяет, что сама цитата
   подтверждает конкретное действие, а не отчёт о проблеме рядом с поручением; классифицирует
   направление и срочность. Типовые сроки нормализует код относительно даты встречи.
   Для других формулировок используется дата LLM; секретарь должен её проверить.
5. Имя сопоставляется с участниками. По выбору пользователя явно названный неизвестный
   человек создаётся backend как гость без email/user_id и добавляется к встрече.
   Существующие однозначные совпадения переиспользуются. При неоднозначности
   остаётся `participant_id=null`, текстовое имя сохраняется. «Ерлан» не
   сопоставляется с отчеством в «Асхат Ерланович». Дописанная моделью фамилия
   без основания в цитате не снимает неоднозначность.
6. Результат сохраняется как поручения-**черновики** и саммари. Утверждает человек.

Пример для встречи 23.09.2026: «Пусть Ерлан до конца недели подготовит претензию» →
«Подготовить претензию», Ерлан, **25.09.2026**. Здесь конец недели принят как ближайшая
рабочая пятница, а не воскресенье. Это явная договорённость прототипа, не универсальная
трактовка. `завтра`/`ертең` → 24.09.2026; `айдың соңына дейін` → 30.09.2026.
`за две недели` → 07.10.2026, `10 дней` → 03.10.2026. Изначальная формулировка срока
сохраняется. Повторные одинаковые действия одного исполнителя объединяются, последняя
формулировка имеет приоритет; уточнения с иной формулировкой действия могут остаться
отдельными черновиками — их нужно проверить.

## Имена по контексту

«Начнём с Батагус Нурлановны» → ближайшая содержательная реплика другого голоса
может быть связана с единственным подходящим участником или автоматически созданным
гостем, если такого имени ещё нет. Роли/местоимения/метки speakerN не создают гостей.
Повторная обработка переиспользует гостя. Проверяются дословная
цитата, маркер передачи слова, порядок реплик и отсутствие пропущенного
содержательного ответа. Короткое «да» не достаточно. Обычное поручение «Ерлан,
подготовь…» не доказывает личность следующего говорящего.

Источник — `llm`, confidence 0,75 — эвристическая метка, не измеренная вероятность.
При противоречии имён одного кластера привязка не делается. Ручная привязка имеет
приоритет; поручения вида «я подготовлю» связаны с меткой `speakerN` и могут
переназначаться через ручную карту спикеров. Автоматическое узнавание по эталону
голоса не реализовано. Ошибки ASR в именах могут помешать сопоставлению.
Одна замена буквы в длинном имени допускается только при совпадающем полном
отчестве/фамилии и единственном кандидате (например, Батагус/Батагос Нурлановна).
Это контекстная гипотеза, которую можно исправить вручную.

## Проверки и приватность

```bash
backend/.venv/bin/python -m pytest pipeline/tests -q
backend/.venv/bin/python scripts/smoke_local_stt.py "pipeline/recordings/Совещание №2.mp3" --min-speakers 2
```

Smoke создаёт новую встречу и оставляет результат для просмотра. Тесты не скачивают
модели. Реальные пробы Qwen на RU/KK/mixed и передаче слова выполнены локально;
это не измерение общей точности на независимом наборе записей.

HTTP-клиент не использует прокси окружения, не следует редиректам, запрещает
публичные адреса и remote/cloud-модели. На локальном сервере обязательно
`OLLAMA_NO_CLOUD=1`. Транскрипт маскируется по телефонам/ИИН перед запросами.
Ошибки модели не включают приватный текст в API/log. Это не полная анонимизация
и не замена сетевой изоляции заказчика. Ответы модели требуют ручной проверки.

Документация провайдера: [Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs),
[настройки и отключение cloud](https://docs.ollama.com/faq).
